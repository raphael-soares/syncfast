# Privacy

syncfast has no server, no account of its own and no telemetry. It sends nothing to its author.

## What leaves your computer

Only what rclone sends to Google Drive to sync the folders you chose: file contents, names and dates, over HTTPS, to your own Drive account. Signing in happens in your browser, between you and Google.

While `syncfast watch` runs, syncfast itself asks the Drive changes API (every 30 seconds) which files changed in your account, to start a sync soon after a change made elsewhere. It sends the access token that rclone saved after you signed in, only to Google, and reads back file IDs and parent folder IDs, not names or contents. See [ADR 0011](../adr/0011-drive-changes-api.md).

Backups go through the same rclone, and only to the destination you chose when you created the backup: a folder in your Drive account, or a folder on this computer or a disk. restic encrypts everything on your computer first, so what reaches Drive (or your disk) is encrypted data files without readable names, sizes or contents. Only you hold the key. A destination on this computer or a disk sends nothing over the network. See [Backing up with syncfast](backup.md).

## What stays on your computer

- **Your OAuth client ID, secret and token** live in `~/.config/rclone/rclone.conf`, readable by your user. syncfast never prints or logs them, and its agent interface never returns them.
- **Sync state, round logs and saved versions** live under `~/.local/state/syncfast/` and `~/.local/share/syncfast/`. Round logs contain file names, and so do the run logs of backups (`~/.local/state/syncfast/backups/<id>/runs/`).
- **The backup key** is generated by syncfast and kept in your desktop's secret storage: the Secret portal, or the Secret Service of your session (GNOME Keyring, KWallet) when the portal is missing. It is never written to a file or a log, never passed to restic as an argument or an environment variable, and never returned to an AI agent. syncfast cannot recover it: write it down when it is shown. The one exception is the file you ask for with **Save Key to File…**, which is not encrypted.
- **Settings** live in `~/.config/syncfast/config.toml`.

## Permissions of the Flatpak

The sandbox is granted: your home folder (the folders you sync and the configs above), the network, a window (Wayland and X11, GPU), external disks under `/run/media` and `/mnt` (backup destinations), the Secret Service on the session bus (the backup key, when the Secret portal is missing), desktop notifications, the tray, the NetworkManager state (to tell offline from an error and to sync when the network comes back), the suspend and resume signal of systemd-logind (to sync after resuming), and `flatpak-spawn --host` to manage its systemd user units. The full reasoning is in [ADR 0006](../adr/0006-flatpak-packaging.md).

## AI agents

An agent you connect through MCP or the CLI runs as you and can read what you can read, so connect only agents you trust. Exploring reads names, sizes and dates, never file contents. An agent cannot sign in, change credentials or confirm a review that deletes files.

Agents never see a backup key. An agent can create a backup, but syncfast generates and stores the key itself and the agent gets only `stored`; no command or tool shows, accepts or returns it, and you are asked to save it. An agent also cannot lower a backup's safety (shorter retention, fewer folders, another destination, turning off **Stay on one file system**) or remove a backup, and it restores only into a new folder. The limit is honest: an agent runs as you, so with the host keyring any process of your session can read the keyring. See the [agent guide](../agents.md).

## Removing everything

Remove the sync in the app, then `flatpak uninstall --user --delete-data io.github.raphael_soares.syncfast`. Delete `~/.config/syncfast`, `~/.local/state/syncfast` and `~/.local/share/syncfast` if you want the state gone too, and revoke access in your [Google account](https://myaccount.google.com/permissions).

**Remove Backup…** never deletes the backup itself: the snapshots stay at the destination, which you delete yourself. Tick **Also delete the key from this computer** to remove the key too; without a saved copy the backup can then no longer be opened.
